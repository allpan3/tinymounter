# TinyMounter 0.1.0 release verification

Date: 2026-11-06. The personal-use 0.1.0 package is built and verified. PR checks, merge and
publication are the final delivery steps. This record does not claim physical-Mac installation.
The user accepted deferring severe system-wide pressure eviction to future validation.
The [earlier acceptance](2026-11-06-personal-use-acceptance.md) retains its other qualifications.

## Package and signing

The production archive contains TinyMounter 0.1.0, build 3, for Apple silicon/macOS 27, install
instructions, MIT terms and LGPL notices. The matching full source archive includes the modified
library and its build scripts. The app links `libTinyMounterSMB.dylib` dynamically; users can
rebuild both with their own development signing. The nine changed upstream library files carry
dated modification notices, checked against the libsmb2 6.3 source archive.

The app and provider retain the physical-Mac installation's development identity, bundle IDs,
App Group and sandbox entitlements. Build 3 supersedes the experimental build 2. No migration,
reset or sandbox change was introduced. Deep/strict signatures pass after ZIP extraction;
both bundles report 0.1.0/build 3 and the packaged notices are present. Development signing is
not Developer ID/notarization; Gatekeeper rejects automatic opening. Certificate expiry is
October 19, 2027. Broader Mac distribution has not been qualified.

## VM verification

In macOS VM 1, macOS 27.0.1 (26A434), `Tools/run-checks.sh` passed after the final Swift change:
518 tests, one optional skip, release CLI checks, generated project consistency, unsigned app
build without Swift warnings, SET_INFO/edit/folder-create checks and 7,205 CCM cases. The later
build-number-only change was rebuilt and its signed package metadata verified.

An isolated `dev.tinymounter.releasecheck` build of the same app source tested first opening
with a simulated Safari quarantine attribute. Privacy & Security → Open Anyway, the second
confirmation and administrator authentication successfully launched it. Launching the
quarantined copy without a Finder move caused `NSFileProviderErrorProviderTranslocated` (-2002).
The app now gives specific Finder installation instructions for that error. This message was
observed on the final Swift code. Quitting, moving through Finder into Applications and reopening
cleared translocation; About displayed Version 0.1.0 and diagnostics showed no locations or shares.
The production identity was not launched against the VM's older fixtures, which include a pending
item. The actual release ZIP was extracted and signature/metadata checked without launching it.

Matched [before](../media/0.1.0-before.gif) and [after](../media/0.1.0-after.gif) recordings show
General → About in the old main build and the release code. Each contains 20 actual VM captures,
cropped to the empty test app window and encoded as GIF. This closes the recording gap noted
in the [icon check](2026-11-06-icons.md). File workflows remain covered by the acceptance record.

The temporary installed VM app was removed. Host signing and packaging remove loose app copies
after archiving. Older VM fixtures and physical-Mac app/data remain unchanged. Raw evidence is
