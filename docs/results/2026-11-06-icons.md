# Selected app and menu icons

The approved TM drive-and-network image is now the app icon, without the wordmark below it.
The menu bar uses matching vector outlines without TM, with warning and download variants.
Existing status priority is unchanged. The icons are integrated and verified in the VM;
the physical Mac's installed app has not been updated.

## Verification

On 2026-11-06, `macOS VM 1`, macOS 27.0.1 (26A434):

- `Tools/run-checks.sh` passed: 518 package tests, one optional skip, release benchmark checks,
  generated project consistency, unsigned app build without Swift warnings, and SMB checks.
- Signed isolated `dev.tinymounter.iconcheck` build passed deep/strict signature validation.
  Finder Get Info displays the selected app icon, and the running app displays the outline
  menu icon. The first launch outside Applications temporarily failed domain enumeration;
  installation in the VM's Applications folder and relaunch cleared it.
- All three compiled menu images load at 22 × 18 points with `isTemplate == true`.
  `CFBundleIconName`/`CFBundleIconFile` identify AppIcon and the compiled ICNS is present.
- The normal, warning and download artwork was inspected in light/dark previews. Live warning
  and download transitions were not repeated; their state selection is unchanged. Switching
  the VM's appearance through AppleScript was denied, so both OS appearances were not exercised.
- Screen video capture exited unsuccessfully. Still images were retained; these do not satisfy
  the PR's before/after recording requirement. Capture a matched pair before opening the PR.

The temporary VM test app was quit, unregistered and removed. The host signing copy was removed
immediately after packaging. No host app build or installation occurred. Older VM fixtures remain.
